## 本片采用的设计判断

这一参考最有价值的是稳定的共同工作视角、坐姿和低干扰的日常动作。优先让 Human 感到 Bot 与自己在同一个安静空间工作；频繁站起和四处游走会破坏这个画面重心。

| 部分       | 本片建议                                                                     | 性质                                 |
| ---------- | ---------------------------------------------------------------------------- | ------------------------------------ |
| 默认构图   | 三分之二侧前方桌边镜头，角色位于右侧；桌面和窗构成前后层次                   | 从截图提炼的本项目设计               |
| 房间       | 自制窗框、桌、椅、台灯、书、杯、显示器与键盘，保持轮廓简洁                   | 自制 Three.js 场景资产               |
| 光线       | 暖夕阳主光与暗室内背景；脸部保留柔和补光                                     | 从截图提炼，不宣称原作渲染参数       |
| 待机       | 坐着呼吸、眨眼，小幅头部变化，手臂保持桌面关系                               | 本项目动作设计                       |
| working    | 在坐姿上叠加轻量手部工作节奏；不自动反推或伪造 Bot 状态                      | 现有 canonical Activity 驱动         |

| 镜头       | 房间／近景／恢复视角；过渡短而平稳，避免自动绕场                             | 本项目可用性设计，非已核验原作功能   |
| 氛围       | 首片夕阳为默认，可有限切换日间／夜晚；只改变呈现                             | 本项目简化，非新的世界时间权威       |
| 站立／走动 | 若实现既定动作验收，只在指定区域和椅子锚点之间；坐姿仍为默认                 | Human 先前提出的扩展，非原作核验功能 |

场景几何和家具尺寸应围绕当前 VRM 的实际骨架高度推导：椅面贴合坐姿臀部，桌面与手腕高度一致；坐下／起身先插值身体位置和腿部角度，再叠加上身动作，避免瞬移。说话不重置身体状态。资源释放、隐藏暂停、降动效、窄面板适配和不可用状态沿用 T1 现有规则。

## 验收建议与范围

验收顺序：默认夕阳桌边画面可读 → Activity working 时坐姿工作 → 真实 Bot 回复时坐着看向 Human 并说话 → 发言结束回到工作方向 → 镜头切换与恢复 → 如本轮实现起身和短距离走动，再验证返回椅子没有明显穿模或滑步。至少检查宽面板和窄面板各一个实际画面。

计时器、任务清单、音乐播放器、剧情、关系成长与衣装系统不进入本次 T1；它们是原作产品功能，不是实现同桌陪伴感的先决条件。保持现有 VRM 与其许可；自制场景素材，不搬运原作角色、音乐、贴图或商标。当前技术样例角色的比例和美术与截图不同，因此可以对齐构图、配色、姿态及交互节奏，不能将结果描述为角色美术的 1:1 复刻。

### 本轮动态房间实现建议

1. **一个连续场景时钟**：默认按浏览器本地时刻取 0–24 小时；昼夜色/太阳角度/灯强由同一纯函数产生。保留明确标记的时间预览供验收，退出预览即返回现实时间；与 Bot Activity 和 speaking 无关。页面隐藏时停止逐帧运算，恢复时直接采样当前时刻，不补跑整段隐藏动画。
2. **时间改变真实光照**：黎明、日间、黄昏、夜晚连续插值；太阳主光位置与窗框/桌上阴影共同变化，夜间主光减弱、台灯渐亮，显示器弱冷光保持面部可读。Sky 负责昼间大气，夜间另用星点/月亮与深蓝天空；不假定 Sky 自带完整夜空。
3. **持续可见的轻动态**：窗外少量有深度的云片缓慢横移（不同距离不同速度）；植物/窗帘缓慢摆动；杯上小范围透明蒸汽。建议 20–60 秒观察能辨别云位移，0.5–2°叶片/窗帘摆幅，以免动效盖过角色。降动效时停环境摆动，仍正确反映当前时刻。
4. **光照和材质分工**：家具用粗糙度较高的 StandardMaterial，金属/玻璃只局部使用；人物保持既有 MToon 并实测其光照表现。RectAreaLight 官方示例使用 StandardMaterial，不可直接假定它能照亮当前 VRM；对角色先用已知可用的 Directional/Hemisphere Light。大面积平面需要窗框阴影、接触暗部和细节几何才能有深度。
5. **可选天气只是呈现**：若本轮仍有余量，可加入清朗/薄云预览；雨滴放在窗外独立层，不穿过屋内人物。不接真实天气 API、不增加世界模拟持久化或后台定时任务。
6. **按真实截图验收**：同一 camera 在 09:00/17:30/22:00 各截图，确认光线、天空、窗外世界和灯具一起变化；录制/间隔截图验证云、蒸汽与角色确实移动；至少测宽 900×600 和窄 360×600 两个 Panel 内容盒，画布无额外留白，脸/关键动作不被底部文字盖住。

若目标是接近原作的成品质感，瓶颈主要是房间/家具建模、材质、灯光和动作的视觉调校。用纯程序几何可以完成可信的第一版小房间，但不能仅增加更多基础方块便宣称达到截图里的美术完成度。更成熟的后续资产路径是自制 Blender GLB + 接触阴影/烘焙 AO + 少量实时灯光和动态物件；本轮仍先围绕一个可验收房间收敛。

补充实机观察：本次也实际打开了 [Bruno Simon 的第一方在线房间](https://my-room-in-3d.vercel.app/)，加载后看到了完整可见的立体房间：书架、工作桌、带曲面和脚轮的椅子、盆栽、沙发、电视和地板木条，具有明显冷暖分区及家具接触阴影。这个外部俯视娃娃屋镜头适合本项目的“房间全景”，而 Chill 式默认陪伴应继续使用人在房内的桌边近景。只核验了画面可渲染，未把其全部控件或性能视为已验证。
